# App Store Review Audit Skill for Codex

[![Tests](https://github.com/maxeriomov-ship-it/app_store-review/actions/workflows/tests.yml/badge.svg)](https://github.com/maxeriomov-ship-it/app_store-review/actions/workflows/tests.yml)
[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

[English version](README.md)

Независимый открытый навык Codex для доказательного аудита приложений перед отправкой в App Store. Он проверяет проекты с iOS-целью, находит потенциальные риски ревью, связывает замечания с актуальными официальными источниками Apple, предлагает точечные исправления и выполняет повторную проверку.

Проект не связан с Apple или OpenAI, не одобрен и не спонсируется ими.

## Какую проблему решает навык

Готовность к App Store Review зависит не только от качества кода. Нужно одновременно проверить Release-конфигурацию, приватность, сторонние SDK, StoreKit, подписки, удаление аккаунта, пользовательский контент, передачу данных AI-провайдерам, metadata, юридические ссылки и доступ ревьюера.

Обычный code review редко объединяет эти области и не всегда отделяет обязательное правило Apple от практической гипотезы. Навык формирует единый повторяемый процесс и честно оставляет статус `Not verified`, когда статический анализ не может подтвердить runtime-поведение или данные App Store Connect.

## Основные возможности

- Полный аудит перед публикацией и быстрая проверка блокирующих рисков.
- Автоматическое определение стека и 15 изолированных read-only сканеров.
- JSON- и Markdown-отчеты со стабильными finding ID.
- Связь замечаний с официальным источником Apple, разделом, применимостью и датой проверки.
- Severity, Verification, Confidence, полнота доказательств, актуальность источников и покрытие аудита.
- Режим Fix только для выбранных пользователем замечаний.
- Recheck по предыдущему JSON-отчету.
- Разбор отказа Apple, подготовка ответа ревьюеру и App Review Notes.
- Проверка материалов App Store Connect.
- Аудит privacy manifest, ATT, required-reason API и сторонних SDK.
- Проверка StoreKit, подписок, встроенных покупок и paywall.
- Отдельные процессы для AI и пользовательского контента.

## Поддерживаемые технологии

- SwiftUI и UIKit
- Xcode projects и workspaces
- Swift Package Manager и CocoaPods
- React Native
- Flutter
- Capacitor
- Expo с нативной iOS-сборкой
- Другие репозитории, содержащие iOS target

## Области аудита

Проверяются состояние проекта и Release-конфигурация, надежность, авторизация и удаление аккаунта, покупки и подписки, приватность, зависимости, системные разрешения, AI-интеграции, пользовательский контент, UI и accessibility prompts, минимальная функциональность, App Store metadata, юридические материалы и маршрут ревьюера.

Статические результаты являются проверяемыми гипотезами, а не автоматическими вердиктами. Исключения из правил, runtime-поведение, backend, содержимое собранного bundle, Sandbox-транзакции и live-данные App Store Connect остаются отдельными ручными проверками.

## Примеры замечаний

- Пустая или слишком общая permission purpose string.
- Staging URL или зарезервированный домен в release-коде.
- Пользовательский placeholder или опасный Swift cast.
- Social login без обнаруживаемого эквивалентного privacy-preserving способа входа с учетом исключений Guideline 4.8.
- Создание аккаунта без обнаруживаемого пути удаления внутри приложения.
- Подписка без обнаруживаемого восстановления покупок или обязательных раскрытий.
- SDK из списка Apple без dependency-specific privacy manifest в доступном исходном дереве.
- Возможная передача персональных данных стороннему AI-провайдеру без обнаруженного раскрытия получателя и явного разрешения.
- Пользовательский контент без обнаруженных report, block, moderation или support controls.
- Неполные доказательства App Store Connect.

Каждое замечание содержит ограничения вывода. Отсутствие ключевого слова не считается доказательством runtime-нарушения.

## Требования

- macOS для Xcode-специфичных проверок.
- Python 3.9 или новее. Сканеры используют стандартную библиотеку Python.
- Codex с поддержкой персональных навыков.
- Опционально: Xcode Command Line Tools.
- Опционально: данные App Store Connect и результаты StoreKit Sandbox для повышения покрытия.

Root-доступ не требуется. Установщик не устанавливает Python-пакеты.

## Установка

Клонируйте репозиторий локально, чтобы проверить код перед запуском:

```bash
git clone https://github.com/maxeriomov-ship-it/app_store-review.git
cd app_store-review
./install.sh
```

Навык устанавливается в:

```text
$HOME/.agents/skills/app_store_review
```

Если установка уже существует, `install.sh` запросит подтверждение и перенесет предыдущую версию в резервную копию с timestamp. Неинтерактивный запуск после проверки кода:

```bash
./install.sh --yes
```

Тестовая установка без изменения персонального каталога:

```bash
CODEX_SKILLS_DIR="$(mktemp -d)" ./install.sh --yes
```

## Обновление

Из локального клона:

```bash
./update.sh
```

Скрипт требует чистый checkout, выполняет `git pull --ff-only`, затем устанавливает новую копию и сохраняет предыдущую установку как backup.

## Удаление

```bash
./uninstall.sh
```

Скрипт запрашивает подтверждение и переносит установленный навык в `.removed-*` backup вместо безвозвратного удаления. Неинтерактивный вариант:

```bash
./uninstall.sh --yes
```

## Явный вызов

Полный аудит:

```text
$app-store-review Проведи полный read-only аудит этого iOS-проекта перед отправкой в App Store.
```

Быстрая проверка:

```text
$app-store-review Быстро проверь блокирующие риски отклонения App Store.
```

Выбранные исправления:

```text
$app-store-review Исправь только выбранные мной finding ID. Сначала покажи точные изменения, затем выполни тесты и Recheck.
```

Разбор отказа:

```text
$app-store-review Разбери полное сообщение об отказе Apple, установи подтвержденную причину, определи необходимость новой сборки и подготовь ответ ревьюеру.
```

## Автоматическое срабатывание

Metadata поддерживает английские и русские запросы:

- «Проверь приложение перед релизом».
- «Проверь приложение перед отправкой в App Store».
- «Проверь paywall перед App Store Review».
- «Найди потенциальные причины отклонения Apple».
- «Разбери отказ Apple и подготовь ответ ревьюеру».
- “Audit this app before App Store submission.”

Навык не предназначен для обычного code review, общего QA или публикации только в Google Play.

## Режимы

### Audit

Режим по умолчанию, ничего не изменяет. Объединяет статические результаты с ручными проверками устройства, backend, Sandbox, юридических материалов и App Store Connect. Профиль `blockers` не может выдать статус `Ready`.

### Fix

Изменяет только явно выбранные замечания. Codex сначала показывает scope, не выполняет общий рефакторинг, добавляет точечные тесты для измененного поведения, запускает сборку и Recheck. Юридический или privacy-текст не придумывается автоматически.

### Recheck

Сравнивает проект с предыдущим JSON-отчетом и разделяет resolved, persisting, new и unable-to-reverify findings.

### Rejection response

Отделяет указанное Apple правило от подтвержденной вероятной причины, проверяет связанный экран, код, metadata или backend, предлагает минимальное исправление, определяет необходимость новой сборки и готовит точные шаги и профессиональный ответ.

## Прямой запуск сканеров

Скрипты работают в read-only режиме:

```bash
python3 "$HOME/.agents/skills/app_store_review/scripts/run_audit.py" \
  "/absolute/path/to/project" \
  --profile full
```

С данными App Store Connect:

```bash
python3 "$HOME/.agents/skills/app_store_review/scripts/run_audit.py" \
  "/absolute/path/to/project" \
  --profile full \
  --asc-metadata "/absolute/path/to/app_store_connect.json"
```

Recheck:

```bash
python3 "$HOME/.agents/skills/app_store_review/scripts/run_audit.py" \
  "/absolute/path/to/project" \
  --baseline "/absolute/path/to/previous-report.json"
```

По умолчанию отчеты создаются во временной папке и не изменяют проверяемый проект.

## Пример резюме отчета

Пример фактического результата для намеренно рискованного fixture этого репозитория:

```text
Readiness: Not ready
Risk index: 72 / 100
Coverage: 51 / 100
Evidence completeness: 100 / 100
Source freshness: 100 / 100

Findings:
- High: 8
- Medium: 9
- Informational: 2
```

Эти числа относятся только к тестовому fixture и конкретному окружению. Они не являются заявлением об эффективности для реальных приложений.

## Индекс риска

Индекс 0–100 — внутренняя взвешенная эвристика для приоритизации замечаний с учетом severity, confidence и verification. Это не статистическая вероятность отклонения Apple и не предсказание решения ревьюера.

## Покрытие аудита

Покрытие показывает долю применимых проверок, для которых получены статические или предоставленные доказательства. Device-only, runtime, Sandbox, backend, legal и App Store Connect проверки остаются `Not verified` до получения доказательств. Высокое покрытие не гарантирует корректность или одобрение.

## Политика официальных источников

Обязательные требования Apple связываются только с официальными страницами Apple. Реестр хранит название, раздел, канонический URL, дату проверки, краткое содержание, применимость и статус источника. Living pages нужно перепроверять при наличии интернета.

Неофициальные статьи, названия пакетов, истории отклонений и статические patterns используются только как гипотезы. Статья Mehran/AetherMaker не копируется в репозиторий и не считается авторитетным источником требований.

См. `app_store_review/references/source_policy.md` и `app_store_review/references/apple_source_registry.json`.

## Ограничения и отказ от гарантий

- Статический анализ не заменяет тестирование на физическом устройстве.
- Simulator не заменяет физическое устройство.
- Metadata-аудит нельзя завершить без актуальных данных App Store Connect.
- Покупки нельзя подтвердить без StoreKit Sandbox или эквивалентной разрешенной среды.
- Исходный код не доказывает все действия SDK, backend или содержимое собранного bundle.
- Некоторые правила Apple требуют контекстной или экспертной интерпретации.
- Прохождение аудита не гарантирует одобрение App Store.
- Проект не является юридической консультацией. Высокорисковые вопросы privacy, consumer protection, договоров и законодательства требуют квалифицированной проверки.

## Сообщить о ложном срабатывании

Используйте [шаблон false positive](.github/ISSUE_TEMPLATE/false_positive.yml). Укажите finding ID, обезличенные доказательства, stack, ожидаемое поведение и минимальный воспроизводимый пример. Не прикладывайте credentials, customer data, закрытый исходный код или signing material.

## Сообщить об изменении правил Apple

Используйте [шаблон Apple guideline update](.github/ISSUE_TEMPLATE/apple_guideline_update.yml). Добавьте каноническую страницу Apple, измененный раздел, effective date и предполагаемое влияние на проверки. Неофициальный материал можно приложить только как гипотезу.
